# 售后反馈工作台

一个纯前端的问题反馈记录工具。打开网页就能记，**内容自动保存**，**截图直接 Ctrl+V 粘贴**，写完一键复制成标准模版文本，粘到群里就能用。

## 它解决什么问题

以前反馈一个问题要重复做这些事：翻上次的模版 → 重新敲门店名、加密狗、系统版本 → 一张张截图另存 → 再一张张上传 → 手写格式。

现在：

| 以前 | 现在 |
| --- | --- |
| 每次都重新敲门店信息 | 把常用的值存成 📌 胶囊，点一下就填入（**不会自动预填，避免带错门店**） |
| 截图要先另存为文件再上传 | 截图后直接在网页上 `Ctrl+V`，立即进附件区 |
| 随手关掉就丢了 | 每敲一个字都**自动存到本机**，关掉再开还在 |
| 手动排版模版格式 + 一张张存图发图 | **「准备发送」一键搞定**：文字进剪贴板，图片批量导出到文件夹 |
| 想滚右栏看历史，整页跟着跑到底 | **左右两栏各自独立滚动**，互不干扰 |
| 一张张发图 | 「打包 zip」导出全部截图为压缩包 |

## 常用信息：📌 胶囊（不再自动预填）

把门店名、加密狗这类常填的值存一次，之后**点胶囊一下填入**：

1. 在字段里填好内容 → 点该字段标签右侧的 **📌**
2. 字段下方会出现一个蓝色胶囊，比如 `📌 满乃是`
3. 以后**点这个胶囊**，值就填进当前字段；再点一次 📌 可取消常用

> **为什么不再自动预填？**
> 每条反馈大多是不同门店。如果新建时自动带着上一单的门店名和加密狗，
> 手一滑就会把 A 店的信息发给 B 客户。所以**新建记录一律全部留空**，
> 常用的值改成主动点选 —— 该省的手续照省，但不会替你「想当然」。

## 界面布局

大屏（宽度 > 1080px）下**整页不滚动**，左右两栏各自独立滚动：

- 左边表单区自己滚，上面的卡片标题「内部售后问题反馈」始终钉在顶部
- 右边侧栏自己滚，看历史记录不会把左边表单一起带跑

窗口窄于 1080px（或手机）时自动退回单列 + 整页滚动。

## 核心：文字是文字，图片是图片

这段反馈发出去要满足两件事 —— **文字能被人搜索到**，**图片是能点开放大的真图片**。
所以工具不去做「合成一张长图」那种做法（长图里的文字搜不到），而是把两者分开准备：

点 **「准备发送」** 一步做完：

1. **文字** → 复制到剪贴板，是**真文本**，粘到群里可以选中、以后搜索得到
2. **图片** → 全部截图按顺序写入下面这个固定的目录结构

然后你到群里：**`Ctrl+V` 粘文字** → 打开那个文件夹**全选图片拖进聊天窗口**。

## 照片存到哪（一条反馈一个文件夹）

所有照片都收在一个固定总目录下，**一条反馈一个独立文件夹**，找照片时直奔「售后反馈照片」即可：

```
你选的文件夹/                    ← 第一次点会弹窗让你选（建议选桌面），之后记住
└── 售后反馈照片/               ← 固定总目录，所有反馈都在这
    ├── 满乃是_20260913_2306/   ← 一条反馈一个文件夹
    │   ├── 01_截图_1.png
    │   ├── 02_截图_2.png
    │   └── 03_截图_3.png
    └── 张三门店_20260914_1015/
        └── 01_截图_1.png
```

- 文件夹名 = **客户名 + 该条记录的创建时间**，同一份反馈**反复导出会写进同一个文件夹**，不会越导越多。
- 侧栏「**照片存到哪**」卡片里实时显示完整的三级路径，还能随时「更改文件夹」。
- 注意：浏览器出于安全**不会暴露文件夹的完整磁盘路径**，只能显示名字，认准目录名去找即可。

### 卡片有两种状态，别搞混

| 状态 | 长什么样 | 含义 |
| --- | --- | --- |
| **还没导出** | 黄色警示条 + 目录行是**虚线灰字**、标「待创建」 | 路径只是**预告**，磁盘上还不存在，得点「导出这 N 张」 |
| **已导出** | 绿色框「✓ 已确认写入 N 个文件」+ **文件清单** | 已经真的写进去了，清单是从磁盘**读回来**的 |

> 导出后会自动**回读目录核对**，只有真的从磁盘读到文件才算成功。
> 如果读回来是空的，会明确报错，**不会**谎报成功。
> 上面那份文件清单就是核对凭据 —— 拿它去系统里对照那个文件夹。

## 四套模版

顶部标签可切换，每套模版各自独立保存草稿，互不干扰：

1. **内部售后反馈** — 客户信息 / 加密狗 / 系统版本 / 设备 / 现象描述 / 实际情况 / 系统显示 / 差异异常 / 操作步骤 / 已尝试处理 / 影响范围 / 紧急程度 + 附件
2. **客户问题回复** — 问候语 → 引用问题 → 原因 → 解决方案 → 后续避免
3. **工单回复客户** — 含钉钉工单编号
4. **排查中回复** — 问题已反馈排查中，给客户先安抚

## 怎么用

- **粘贴截图**：截好图（Win + Shift + S 或 QQ/微信截图），在网页任意位置按 `Ctrl+V`。
- **存为常用**：填好门店名 / 加密狗 / 系统版本后，点字段标签右侧的 📌，以后新建自动带上。
- **复制发群**：右侧预览区点「复制全文」，再到群里粘贴。
- **发图**：缩略图右上角 📋 可把单张图复制到剪贴板直接粘进聊天窗口；「打包下载」导出全部。
- **找回旧记录**：右侧「历史记录」点一下即可继续编辑；支持关键词搜索。
- **备份 / 换电脑**：顶部「导出」生成一个 JSON 备份文件，「导入」可在另一台设备恢复（含图片）。

## 数据在哪

全部存在**你自己浏览器的 IndexedDB** 里，页面不上传任何数据，也没有后端。
换浏览器、换电脑、清空浏览器数据都会导致记录丢失 —— 重要内容请偶尔「导出」备份一次。

## 本地运行

因为浏览器对 `file://` 下的本地数据库有安全限制，**建议用本地服务器打开**：

```bash
# 任选其一
python -m http.server 8000
npx serve .
```

然后访问 `http://localhost:8000`。

线上访问 GitHub Pages 地址即可（HTTPS，功能完整）。

## 技术

无框架、无构建、无依赖 —— 只有 `index.html` / `styles.css` / `app.js` 三个文件。
ZIP 打包是自己实现的极简 store-only 写入器，不引第三方库。

### 遇到功能异常怎么办

先按 **`Ctrl + F5`** 强制刷新。

页面右上角有版本号（当前 `v3.2`）。GitHub Pages 和浏览器都会缓存旧文件，
如果页面像是「按钮点了没反应」「粘贴没反应」，基本是 HTML 和 JS 版本对不上导致的，
强制刷新即可。

代码里对此也做了防护：**任何一个按钮找不到都不会影响其他功能**，
粘贴图片、自动保存这些核心能力会优先绑定，不会被别的地方的错误连累。

### 导出没成功怎么查

按这个顺序排：

1. **卡片是不是黄条 + 「待创建」？** 那就是**还没点导出**，不是失败。
2. 点了导出但报错 → 看报错文字。常见原因是选中的文件夹**不允许写入**
   （比如选到了系统目录、只读盘、或 OneDrive 里未同步的位置），换个文件夹再试。
3. 导出显示成功 → 卡片里有绿色「✓ 已确认写入 N 个文件」和文件清单 →
   打开 `你选的文件夹 / 售后反馈照片 / 客户名_日期_时间/` 核对，文件名应该和清单一模一样。
4. 文件都在但想不通在哪 → 浏览器**不提供完整路径**，只能凭文件夹名字在系统里找。
   建议一开始就选一个专门的文件夹（比如桌面上的 `001`），别每次都换。

### 开发者备注

- 数据层：IndexedDB，三个 store —— `records` / `images` / `meta`，记录与图片分表存储。
- 调试入口：浏览器控制台里的 `window.__FB`，可查看 `state`、`TEMPLATES`、`PHOTO_ROOT` 等。
- 文件夹导出依赖 File System Access API（Chrome / Edge 支持，Firefox / Safari 不支持，会降级为逐张下载）。
